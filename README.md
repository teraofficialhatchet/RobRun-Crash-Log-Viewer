## RobRun Crash Log Viewer

The RobRun Crash Log Viewer is a dedicated reader and analyzer for the crash logs generated by RobRun. It parses raw dump data into a clean, hierarchical view, enabling operators to quickly locate the root cause, trace stack frames, and extract memory snapshots. Designed for speed and clarity, the viewer supports the latest crash dump format and delivers a customizable display that can be tailored via configuration profiles.

---

## Core Features

- **Structured Parsing** – Converts the binary crash dump into a nested JSON structure that preserves module, thread, and stack information.
- **Interactive Tree View** – Clickable nodes reveal register states, instruction pointers, and associated source symbols (if available).
- **Profile‑Based Display** – Three built‑in profiles (``, ``, ``) control which columns appear, their ordering, and formatting. A fourth user‑defined profile (``) can be created to add or hide fields.
- **Export Options** – Logs can be exported as HTML, CSV, or plain text, preserving the visual hierarchy for offline review.
- **Search & Highlight** – Full‑text search across all fields, with optional regex support, and the ability to pin search results for later reference.
- **Batch Analysis** – Process an entire folder of crash dumps in a single run, generating a consolidated report with timestamps and error categories.

## Quick Start

1. Download the latest release bundle from the **Download** badge above.
2. Unpack the archive to a directory of your choice; the executable `rclv` is located in the root.
3. Launch the viewer by double‑clicking `Release` (Windows) or running `./rclv` on Linux/Mac.
4. Drag the target crash file into the window or use the *Open* menu to locate it.
5. The viewer will load the dump, build the tree, and display the default profile.
6. To switch profiles, click **Profile → Load** and choose one of the preset `.cfg` files.

For advanced users, edit the configuration files to customize column visibility and ordering. Each profile file follows a simple key‑value format, e.g.:

```
[Columns]
module=true
thread=false
stack=true
memory=true
```

## FAQ & Troubleshooting

**Q1 – Why does the viewer show “Unknown” for symbols?**
A1 – Symbol resolution requires access to the original debugging symbols or a symbol server. If the symbols are missing, the viewer will display “Unknown” in place of the function name. Ensure that the symbol files (`.pdb` on Windows, `.dSYM` on macOS) are located alongside the crash dump or that a symbol server path is configured in the profile.

**Q2 – The tree expands too slowly for large dumps.**
A2 – Large dumps (hundreds of megabytes) can strain the parsing engine. Enable the *Lazy Loading* option under *Settings → Performance* to defer loading of sub‑nodes until they are expanded.

**Q3 – I receive “Memory access violation” errors while opening a file.**
A3 – This usually indicates corruption or truncation of the crash dump. Verify file integrity with a checksum and retry. If the file is still problematic, try opening it with the *Batch Analysis* mode; sometimes the viewer can recover partial data.

**Q4 – Can I automate reporting across multiple servers?**
A4 – Yes. Use the *Batch Analysis* CLI flag (`--batch <directory> --report <output.html>`) to process all dumps in a folder and generate a single HTML report that aggregates timestamps, error codes, and stack summaries.

**Q5 – How do I add a new column to the view?**
A5 – Edit `` and add a new entry under `[Columns]`, for example `error_code=true`. Save the file and reload the profile from the menu.
